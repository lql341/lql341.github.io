Summary

MinerU 4.0.7 has passed functional checks, but the available production evidence does not justify replacing 3.4.4. Keep the production and experimental environments separate; do not upgrade the production environment in place.

Unified runtime closure

CentOS 7's glibc 2.17 cannot directly load some wheels. Both environments reuse the same principle:

module purge
module load compiler/gcc/12.2.0 compiler/dtk/26.04

<GLIBC_2_28_LD_SO> \
  --library-path "<GLIBC_LIB>:<GCC_LIB>:<DTK_LIBS>:<SYSTEM_LIBS>" \
  <VENV>/bin/python "$@"

sitecustomize.py At the same time, point the multiprocessing spawn worker to the launcher to prevent the child process from falling back to the system glibc.

Do not misread

Standard is loaded for the first time, and Advanced reuses the VLM in the same process; the two cannot be ranked based on quality or speed. This set of data only proves that all four gears can complete real analysis in the target environment.

MinerU Drop batch-processing interface

native push file/directory │ ▼ Shared inbox ─ SHA256 / number of pages / chunking plan │ ▼ Slurm job array ─ One DCU per worker, model resident, atomic pick-up task │ ▼ afterany CPU merge ── Markdown / JSON / images / manifest │ ▼ status / retry / fetch

adapter implements

remote rootversionPurpose
mineru-drop3.4.4Stable production default
mineru4-drop4.0.7 Basic/TorchNew version of protocol and experimental batch
# 3.4.4
mineru-drop push <PDF_OR_DIRECTORY>

# 4.0.7
mineru-drop --remote-root mineru4-drop push <PDF_OR_DIRECTORY>

# 通用
mineru-drop [--remote-root ...] status --batch <BATCH_ID>
mineru-drop [--remote-root ...] retry  --batch <BATCH_ID>
mineru-drop [--remote-root ...] fetch  --batch <BATCH_ID>

The long document defaults to 128 pages or less, and will be divided into 96 pages if it exceeds 128 pages. A small number of long documents are given priority to 1 worker, Avoid multiple workers each responsible for a model cold start; expand to 4 workers for a large number of documents.

Complex page parsing evaluation

Standard / Advanced
Only manually specify small batches and does not enter the default automatic routing.

需要最终 Markdown / JSON  → 3.4.4 pipeline
必须使用 4.x schema       → 4.0.7 Basic
极复杂页面、人工复核      → Standard / Advanced
11

Reproduction procedure and scope

Minimum recurrence constraint

  • The login node prepares dependencies and models; the computing node runs offline.
  • module must be loaded before venv.
  • The main process and the spawn child process must share the glibc 2.28 launcher.
  • Slurm scripts must pass real workload exit codes.
  • 4.0.7 ONNX Runtime 1.20.1 uses relabeled wheel and can only run under external glibc 2.28.
