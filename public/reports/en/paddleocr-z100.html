PaddleOCR on Hygon Z100

Compatibility and deployment validation for PaddleOCR 3.7.0 / PaddleX 3.7.2 through the Transformers/PyTorch backend, with a same-document comparison against MinerU.

Translation scope: This page is an English summary of the Chinese report, not a line-by-line translation. The complete Chinese report is linked below.

Executive summary

PaddleOCR 3.7.0 and PaddleX 3.7.2 completed end-to-end inference on one Hygon Z100 (gfx906) card through the Transformers/PyTorch route. A 23-page PDF achieved a measured steady-state throughput of 0.49 pages/s. This is an OCR throughput result for the tested document and configuration; it is not an accuracy score.

PaddleOCR and MinerU serve different purposes. PaddleOCR is an OCR engine; MinerU is a document-parsing pipeline that also handles layout and structured elements. Similar character counts do not establish equivalent recognition accuracy or document structure.

Environment and software

The test used an isolated PaddleOCR/PaddleX package tree on the recorded Python 3.10, PyTorch 2.7.1, DTK 26.04, and user-space glibc 2.28 runtime. The existing MinerU environment was not modified. The host's legacy glibc and older packaged Python/Torch stack could not directly support the newer PaddleOCR dependency set.

The runtime launcher must provide the same library closure to the worker process, including the loader, device runtime, and required shared libraries.

Backend selection

The tested deployment uses PaddleOCR's Transformers/PyTorch path. This route reuses the validated DCU PyTorch runtime while keeping PaddleOCR dependencies isolated. The result does not establish support for every Paddle backend or every model configuration.

Compatibility validation

Validation covered package imports, device enumeration, model loading, image inference, worker startup, and process exit status. The service path is launched with a controlled runtime environment. A worker health check should include device visibility, model initialization, one-image inference, and a clean exit or successful request response.

Performance results

For the 23-page Mooncake-v3 PDF, steady-state throughput was 0.49 pages/s. The report also records a same-document comparison with MinerU: the measured OCR-only PaddleOCR path was approximately 1.9 times faster in steady state for that run. MinerU's pipeline performs additional document-structure work, so the throughput figures do not represent equivalent output scope.

Cold-start and model-loading costs must be reported separately from steady-state inference. The measurements are tied to the tested model, input, device, and runtime conditions.

Output quality and scope

No manually annotated character-level ground truth was available for this test. Therefore, character-count differences and confidence scores are not presented as accuracy measurements. The report's output review records recognition issues in the tested document; broader accuracy claims require labeled samples and a defined scoring procedure.

Use PaddleOCR for batch OCR, targeted re-recognition, or low-latency text extraction. Use MinerU when the required output includes document layout, tables, equations, images, or structured Markdown.

Deployment and acceptance

  • Keep PaddleOCR dependencies in an isolated package tree.
  • Launch workers through the tested user-space runtime wrapper.
  • Run one persistent worker per allocated DCU and feed it a batch of pages.
  • For production acceptance, verify repeatability, failure handling, memory behavior, and output quality on representative labeled documents.

Reproduction and limitations

Reproduction requires the stated package versions, runtime closure, device allocation, model, and PDF. The 0.49 pages/s value is a single-workload steady-state measurement, not a general service-level guarantee. Accuracy remains unquantified without ground truth.
