Bilingual XeLaTeX Research Typesetting

A reproducible toolchain smoke test for Chinese-English research documents, mathematics, figures, code, cross-references, and bibliographies.

Translation scope: This page is an English summary of the Chinese report, not a line-by-line translation. The complete Chinese report is linked below.

Summary

A compact three-page sample was used to validate the main features required by a bilingual research-writing workflow. The build completed with XeLaTeX and Biber and covered mixed Chinese and English text, mathematical notation, tables, TikZ, PGFPlots, source code, cross-references, and bibliography output.

The sample is an installation and regression test, not a paper template or a complete evaluation of every package used by a research group.

Scope and acceptance criteria

The smoke test checks whether a clean environment can build a short document and whether key output features render as expected. Acceptance includes successful compilation, correct CJK and Latin text, stable numbering and references, visible plots and diagrams, and a bibliography produced by Biber.

Feature coverage

  • Bilingual paragraphs, punctuation, bold, italic, monospaced text, and footnotes.
  • Document hierarchy, table of contents, nested lists, page numbers, and cross-references.
  • Mathematics, theorem-like structures, tables, and units.
  • TikZ diagrams, PGFPlots figures, and code listings.
  • Biber bibliography generation and citation links.

The report records nine core checks as passing. The rendered sample pages are available in the Chinese edition.

Reproducible build workflow

Use the documented build sequence from a clean project directory and retain the compiler output. When bibliography data or citations change, run the bibliography tool and subsequent XeLaTeX passes required to resolve citations and references. A successful first compiler invocation alone is not sufficient evidence that cross-references and the bibliography are complete.

Font and layout findings

Font selection can differ between desktop applications and command-line builds because they may use different font databases or caches. Do not attribute a rendering difference to one font file without checking the font selected by the process, the available font set, package changes, and the result after restarting the relevant process.

The report separates blocking build failures from non-blocking layout improvements. The test is intended to reveal missing fonts, packages, plotting dependencies, numbering issues, and bibliography-toolchain problems early.

Environment and privacy

The public report omits local usernames, absolute paths, device identifiers, and environment logs. Reproduction should record the TeX distribution, package versions, fonts, Biber version, and build commands for the target system.

Conclusion

This sample is suitable as a baseline acceptance test for a Linux research-writing environment. It provides a repeatable check of common bilingual typesetting components; it does not guarantee identical rendering across operating systems, TeX distributions, or font packages.
