🔧 三、源码编译过程与主要难题

3.1 版本选择

最新稳定版 GROMACS 2026.3（2026 年 8 月发布）。 使用 DTK 26.04（集群最新 DTK）的 HIP 原生后端，目标架构 gfx906。

3.2 编译配置

cmake ../gromacs-2026.3 \
  -DGMX_BUILD_OWN_FFTW=ON \
  -DGMX_GPU=HIP \
  -DGMX_MPI=ON \
  -DCMAKE_C_COMPILER=gcc-11.2 \
  -DCMAKE_CXX_COMPILER=g++-11.2 \
  -DCMAKE_HIP_COMPILER=<DTK_ROOT>/llvm/bin/clang++ \
  -DCMAKE_PREFIX_PATH=<DTK_ROOT> \
  -Damd_comgr_DIR=.../lib64/cmake/amd_comgr \
  -DGMX_SIMD=AVX2_256 \
  -DGMX_GPU_FFT_LIBRARY=rocFFT \
  -DGMX_GPU_NB_DISABLE_CLUSTER_PAIR_SPLIT=ON \
  -DGMX_HIP_TARGET_ARCH=gfx906 \
  -DCMAKE_BUILD_TYPE=Release

3.3 编译问题排查（8 个坑）

  1. 1 CMake 版本不满足
    GROMACS 2026.3 要求 CMake ≥ 3.28，集群最高仅 3.25.0。CMake 3.30 预编译包下载超时失败。
    Patch 所有 CMakeLists.txt 中的 cmake_minimum_required(VERSION 3.28) → 3.25（含子目录 muparser, googletest, tng_io 等共 8 处）。
  2. 2 amd_comgr 找不到
    DTK 26.04 将 amd_comgr cmake 文件放在 lib64/cmake/，而 hip-lang-config.cmake 从 lib/cmake/ 查找。CMAKE_PREFIX_PATH 无法传递到 try_compile 子进程。
    设置环境变量 export amd_comgr_DIR=.../lib64/cmake/amd_comgr。
  3. 3 GPU 架构硬编码 gfx90a
    GROMACS cmake 中 gmxManageHipccConfig.cmake 硬编码 --offload-arch=gfx90a 作为测试基准。DTK 26.04 没有 gfx90a 的 device library。
    Patch gmxManageHipccConfig.cmake 将 gfx90a → gfx906。
  4. 4 计算节点无外网，FFTW 下载失败
    GROMACS 自带的 FFTW 构建会在 make 阶段从 fftw.org 下载源码，计算节点无法解析域名。
    本地下载 FFTW 3.3.10 (MD5: 8ccbf6a5...)，scp 上传到集群，在 cmake 之后、make 之前预置到 build 目录。
  5. 5 HIP 编译缺 <filesystem> 头文件
    DTK 26.04 的 Clang 17.0.0 无法自动找到 GCC 11.2.0 的 C++ 标准库（GLIBCXX_3.4.29）。
    添加 --gcc-toolchain=<GCC_ROOT> 到 HIP 编译标志。
  6. 6 运行时 libstdc++ 版本不匹配
    二进制链接了 GCC 11.2.0 的 libstdc++，但运行时系统加载 GCC 9.3.0 的库（缺 GLIBCXX_3.4.29 / CXXABI_1.3.13）。
    在作业脚本中设置 LD_LIBRARY_PATH 指向 GCC 11.2.0 的 lib64。
  7. 7 SIMD 自动检测失败
    CMake 在计算节点上的 SIMD 检测程序运行失败，导致 SIMD 被禁用（显著影响 CPU 端性能）。
    手动指定 -DGMX_SIMD=AVX2_256（Hygon C86 7185 支持的最高级别）。
  8. 8 --gcc-toolchain 泄漏到 CXX 编译器
    通过 -DCMAKE_HIP_FLAGS 传递的 --gcc-toolchain 被 CMake 3.25 同时应用到 CXX 编译，GCC 不识别该 flag 导致 macro names must be identifiers 错误。
    移除 CMAKE_HIP_FLAGS，改用环境变量 HIPCC_COMPILE_FLAGS_APPEND 传递。

🔬 六、性能瓶颈分析

6.1 三大核心瓶颈

  1. Force 计算（7.8× 差距）——非键相互作用力在 GPU 上的计算。 CUDA 兼容层（nvcc→PTX→gfx906 ISA）生成的机器码对 Vega20 架构有更好的指令调度和寄存器分配； HIP 原生后端的 Clang 17 生成的 gfx906 代码可能未充分利用硬件特性。
  2. NB X/F buffer ops（100× 差距）——非键力/坐标 buffer 在 CPU 与 GPU 之间的传输。 CUDA 版每 10 步传输 1 次（51 次/500 步），HIP 版每 5 步传输 1 次（101 次/500 步），且单次传输耗时 5.3ms vs 0.1ms。 怀疑 HIP 版将 PME force reduction 部分回退到了 CPU 执行，导致更大的数据搬运量。
  3. Reduce GPU PME F（53× 差距）——PME 力在 GPU 上的归约。 CUDA 版 0.010s 完成，HIP 版 0.534s。这个差距强烈暗示 HIP 版在 CPU 上做 PME reduction， 而非 GPU 端原位归约。CUDA 版通过 cuFFT 在 GPU 端完成整个 PME 流程。

6.2 根因推断

DTK 23.10 的 CUDA 兼容层生成的 GPU 代码质量优于 DTK 26.04 原生 HIP 后端。 具体而言：

  • DTK 23.10 的 nvcc 将 CUDA kernel 编译为 PTX 中间码，再由 HIP runtime 翻译为 gfx906 ISA。这条路径经过海光充分优化，针对 Z100 的 64-wide SIMD 单元和寄存器文件做了专门调度。
  • DTK 26.04 的 Clang 17 直接编译 HIP kernel 到 gfx906 ISA。生成的代码可能使用了通用路径，未针对 Vega20 的特定微架构（如 64-wide wavefront、特定的 LDS 带宽）做优化。
  • GROMACS 2026.3 的 HIP 后端可能在某些 GPU 操作（如 PME force reduction）上回退到了 CPU 路径，而 CUDA 后端在 GPU 端完成全程。

🧭 七、经验总结与通用建议

7.1 有效经验

  1. CMake 版本不够可以 patch——GROMACS 2026.3 实际在 CMake 3.25 上可正常工作，官方 3.28 要求是预防性的。
  2. SIMD 必须手动指定——在计算节点上编译时，CMake 的 SIMD 检测程序可能因缺少运行时环境而失败，建议始终显式设置 -DGMX_SIMD=AVX2_256。
  3. FFTW 等外部依赖需预下载——计算节点无外网是国产超算的普遍情况，任何需要下载的构建步骤都必须在登录节点完成并预置。
  4. GCC 版本管理要小心——自装 GCC 的 libstdc++ 与系统默认版本不兼容时，需要同时设置 PATH 和 LD_LIBRARY_PATH。
  5. DTK 的 lib64 vs lib 路径问题——DTK 将部分 cmake 模块放在 lib64 而非 lib，需要手动设置 *_DIR 环境变量。

7.2 不成功的尝试

  1. CUDA 后端 + DTK 26.04——DTK 26.04 已移除 CUDA 兼容层（无 nvcc），无法走此路径。
  2. CUDA 后端 + DTK 23.10——GROMACS 2026.3 要求 CUDA ≥ 12.1，而 DTK 23.10 仅提供 CUDA 11.8，版本不匹配。
  3. 从 GitHub 下载 CMake 预编译包——GitHub 在集群上不可达，cmake.org 下载超时。最终通过 patch 使用了系统 CMake 3.25。
  4. -update gpu 运行时选项——导致矩阵求逆错误（determinant too close to zero），对小体系水盒子不适用。
  5. rocFFT 替代 VkFFT——对 PME 性能无明显改善（0.679s → 0.765s），瓶颈不在 FFT 库本身。
  6. 关闭 super-cluster（2×2×2 → 1×1×1）——对总体性能影响极小（17.61 → 17.74 ns/day），瓶颈不在聚类策略。

7.3 关键结论

  1. 在 Z100 (gfx906) 上，DTK 23.10 的 CUDA 兼容层是当前最优的 GROMACS GPU 后端， 性能约为 DTK 26.04 原生 HIP 后端的 2.6 倍。
  2. 如需使用最新 GROMACS 版本（2024+），建议尝试：
    • Patch GROMACS 的 CUDA 最低版本要求，用 DTK 23.10 的 CUDA 兼容层编译
    • 或用 DTK 26.04 编译 GROMACS 2024.x（可能没有 2026.3 的严格 CUDA 12.1 要求）
    • 或用 SYCL/AdaptiveCpp 后端（未经测试）
  3. HIP 原生后端的性能问题集中在 Force 计算和PME reduction， 如果 DTK 后续版本改进 Clang 对 gfx906 的代码生成，差距有望缩小。
  4. 对于生产使用，建议继续使用集群预编译的 GROMACS 2023.2 CUDA 版本， 其性能稳定且经过充分验证。

📌 八、后续工作建议

  1. Patch CUDA 版本要求——修改 GROMACS 2026.3 的 GMX_CUDA_MINIMUM_REQUIRED_VERSION，用 DTK 23.10 的 CUDA 兼容层编译，预期可达到接近预编译版的性能。
  2. HIP 内核 profiling——使用 rocprof 对 HIP 版的 Force kernel 和 PME reduction 做详细分析，确认是否回退到 CPU 路径。
  3. 多卡扩展测试——测试 2/4 卡 Z100 的 scaling 效率，HIP 和 CUDA 后端在多卡场景下可能有不同表现。
  4. 尝试 GROMACS 2025.x——可能对 HIP 和 CUDA 版本要求更宽松。
  5. 关注 DTK 更新——DTK 26.04 之后版本可能改进 gfx906 的代码生成质量。
