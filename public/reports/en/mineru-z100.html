ENGLISH TECHNICAL SUMMARY · 2026-09-27 · HYGON Z100 / GFX906

MinerU on Hygon Z100

Production baseline for MinerU 3.4.4 and controlled evaluation of MinerU 4.0.7, including throughput, functional checks, deployment choices, and operating limits.

Translation scope: This page is an English summary of the Chinese report, not a line-by-line translation. The complete Chinese report is linked below.

Executive summary

MinerU 3.4.4 remains the production baseline because it has measured service-pool throughput and stability evidence. MinerU 4.0.7 passed the reported functional checks, but those checks do not establish production readiness or justify replacing the 3.4.4 service.

  • MinerU 3.4.4 pipeline: 955 documents/hour on a four-card service pool at concurrency 12.
  • Soak validation: 72 requests, no failures or rejections, and no observed RSS growth over the measured interval.
  • MinerU 4.0.7: four of four reported functional checks passed. Performance and production stability evidence remain narrower than for 3.4.4.
  • For batch document parsing, retain the 3.4.4 pipeline. Treat 4.0.7 Flash and Basic as separate evaluation paths with workload-specific constraints.

Scope and method

The evaluation separates production and experimental tracks. Results from different versions, modes, page counts, and warm or cold states are not combined into a single speed ranking. The 3.4.4 service-pool result comes from the recorded soak run; 4.0.7 checks establish the listed functions only.

The public edition omits cluster addresses, ports, usernames, absolute paths, node names, and job identifiers. The companion Chinese archive contains additional failure traces and commands.

Platform and runtime

Tests were performed on Hygon Z100 (gfx906) under the recorded DTK 26.04 software stack. The deployment uses a user-space runtime closure to accommodate the host system's older glibc. Child processes must inherit the same loader and library environment as the parent process; successful imports in the parent alone do not establish that condition.

MinerU 3.4.4 production baseline

The pipeline backend is the validated production route. The four-card pool sustained 955 documents/hour at concurrency 12 in the recorded workload. A 72-request stability run reported zero request failures, zero rejections, and no RSS increase between the measured endpoints. These values apply to the stated service configuration and workload.

For repeated document processing, a persistent worker pool avoids paying model initialization costs for every document. The report's deployment evidence includes backpressure and worker recovery checks; it does not imply identical performance under different document mixes or cluster contention.

MinerU 4.0.7 evaluation

Version 4.0.7 was evaluated in an isolated experimental environment. Four functional checks passed. The result supports further evaluation, not an in-place production upgrade.

  • Flash: suitable for rapid first-pass scanning where its output and quality meet the downstream requirement.
  • Basic: ONNX Runtime CPU execution was measured with 8- and 16-thread configurations. On Z100, the model should remain resident when processing batches.
  • Standard / Advanced: keep as explicitly selected experimental routes for small batches until broader functional and performance evidence is available.

Deployment recommendation

Use MinerU 3.4.4 pipeline for final batch parsing. Use 4.0.7 Flash for preview or indexing only after validating output quality for the target corpus. Route 4.x Basic through the tested ONNX CPU configuration or a persistent Z100 worker. Do not route complex pages automatically to Standard or Advanced based on the current evidence.

Reproduction and limitations

Reproduction requires the same package versions, user-space runtime closure, device allocation, workload, and warm-up policy. Validate worker startup, model loading, request completion, process exit status, and memory behavior at the service boundary. Throughput is workload-specific; the 4.0.7 functional pass count is not a comparative performance result.
