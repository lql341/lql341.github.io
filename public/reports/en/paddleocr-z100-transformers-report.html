1. Final conclusion

PaddleOCR 3.7.0 completed end-to-end functional verification on Kunshan Z100 through the Transformers/PyTorch backend. The deployment uses a user-space glibc 2.28 loader, GCC 12.2, DTK 26.04, and a Hygon-adapted Torch 2.7.1 build. It does not depend on a PaddlePaddle DCU wheel.

Inference backend selection

Kunshan module mainly stays at Python 3.7/Torch 1.10; PaddleOCR 3.7/PaddleX 3.7 uses Python 3.8 syntax and modern Transformers API. Direct force installation to Python 3.7 will trigger positional parameter syntax, walrus expressions and typing/importlib API errors.

MinerU reports have verified more suitable user-mode closures: Python 3.10, Torch 2.7.1, DTK 26.04, user-mode glibc 2.28. In this article, without modifying MinerU, we only read-reuse its Torch/runtime library and install PaddleOCR/PaddleX in a separate directory.

computing node has no external network, so the model is downloaded from BOS to the new cache at the login node; the computing node only sets HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1to avoid runtime DNS timeouts.

Deployment Plan

8.1 unified launcher

system glibc 2.17 cannot directly host the new Torch wheel. The production process must pass the user mode glibc 2.28 loader, and the closure includes GCC 12.2, DTK 26.04,dcc/gcvm and rocm_smi。

<PADDLEOCR_ROOT>/bin/dcu-python your_worker.py

Do not call bare python. Don't let Python's spawn child process go back to naked sys.executable; sitecustomize.py has been set multiprocessing.set_executable()。

8.2 Resident worker

  • Each DCU starts a resident PaddleOCR worker.
  • model is only loaded once and will receive requests in a stable state.
  • The queue layer limits the concurrency of the same worker to avoid model thread safety and video memory contention.
  • worker health checks must include device enumeration, model loading, single image inference, and exit codes.
  • All models are fixed to the local cache, the production process sets offline variables, and implicit downloading of the request path is prohibited.

11. Known limitations and follow-up suggestions

Accuracy:currently has no official OCR ground truth. Character-level, row-level or field-level evaluation of business data sets should be supplemented before production goes online.

Performance:The current attention/BLAS path of gfx906 has an architecture rollback; you need to re-benchmark after upgrading DTK or Torch.

Model:This article fixes PP-OCRv5 mobile det/rec. The default path of PP-OCRv6 requires additional downloading of the model, and the computing node cannot temporarily access the external network.

Concurrency:currently only tests a single card and a single worker. Doka production recommends one process per card, and first conduct 1/2/4 card throughput and stability tests.

Document analysis:If the requirements include tables, formulas, pictures and Markdown structures, it is more reasonable to continue using MinerU; PaddleOCR as an OCR sub-service.

Environmental drift:If any of the loader, model cache, module, Torch, and Transformers is moved or upgraded, §9 must be re-executed to reproduce.
