waterbox8 test results and reasons for changes

In the previous report, waterbox8 NPT measured 15.31 vs 41.22 (HIP slower 2.7×), this was the judgment at that time The only basis for lower HIP performance. The idle node retest results are as follows:

HIP 2026.315.31 (affected by competing loads)67.64

Cause: HIP backend performance is significantly affected by node CPU contention load.On the same competing node, HIP dropped from 148 to 9.4 (15× worse), while the CUDA translation barely moved (steady at 66.8). The waterbox8 HIP numbers from the previous edition fell exactly Fight for the node. From this, the entire optimization issue of "waterbox8 NPT is slow" (viral rollback, DPP reduction, register/occupancy) All are based on measured values affected by competing loads; the retest results of relevant optimization assumptions are shown in Section 4.

Build issues and performance analysis

Compile-time configuration errors and their manifestations

gfx90a→gfx906 probe pit: gmxManageHipccConfig.cmake Use --offload-arch=gfx90a to detect whether hipcc supports various optimization flags, but DTK 26.04 does not have gfx90a Device library - every probe fails withAll optimization flags are silently discarded, performance drops to ~17 ns/day and No errors are reported. Fix: Change probe architecture to gfx90a changed to gfx906(and supplement -mcpu=gfx906, remove gfx906 and do not recognize -fno-gpu-rdc / -fno-slp-vectorize）。 This is the compilation change with the greatest impact.

Benchmark requirements:A reproducible baseline should be established before optimization. Node resource contention will affect measurement results, and kernel-level optimization based on disturbed data may lead to incorrect judgments.

Benchmark test preconditions

Baseline node status:HIP backend is more sensitive to CPU resource contention (the performance difference in this test is up to about 4×), The CUDA translation version is relatively stable. Suggestion: ① squeue Confirm that the node has no other jobs or --exclusive exclusive; ② Repeat 3 times for each point,sd > 2% will be judged as contaminated and re-run（gmx_bench.slurm is built in); ③ When comparing across nodes, both backends should be run on the same batch of exclusive nodes.

Build procedure and reproduction steps

tool chain：DTK 26.04（HIP 6.3.26113 / clang 17）+ GCC 12.2.0 + CMake 3.28.6 + OpenMPI 4.1.5。

# 0. 恢复 cmake_minimum_required 到 3.28（撤销任何 3.25 降级补丁）
cd $SRC
sed -i 's/cmake_minimum_required(VERSION 3\.25)/cmake_minimum_required(VERSION 3.28)/g' CMakeLists.txt
find . -name CMakeLists.txt -exec sed -i 's/cmake_minimum_required *(VERSION 3\.25)/cmake_minimum_required(VERSION 3.28)/g' {} \;

# 1. gfx906 架构探针补丁（关键，见 4.1）
cd $SRC/cmake
sed -i 's/--offload-arch=gfx90a/--offload-arch=gfx906/g' gmxManageHipccConfig.cmake
sed -i 's/gmx_hip_check_single_flag("-fno-gpu-rdc")/# REMOVED for gfx906: gmx_hip_check_single_flag("-fno-gpu-rdc")/' gmxManageHipccConfig.cmake
sed -i 's/gmx_hip_check_single_flag("-fno-slp-vectorize")/# REMOVED for gfx906: gmx_hip_check_single_flag("-fno-slp-vectorize")/' gmxManageHipccConfig.cmake
sed -i '/gmx_hip_check_single_flag("-ffast-math")/a\    gmx_hip_check_single_flag("-mcpu=gfx906")' gmxManageHipccConfig.cmake

# 2. 环境
module purge
module load mpi/openmpi/gcc-9.3.0/4.1.5
source <DTK_ROOT>/env.sh
export PATH=<GCC_ROOT>/bin:$PATH
export LD_LIBRARY_PATH=<GCC_ROOT>/lib64:$LD_LIBRARY_PATH
export amd_comgr_DIR=<DTK_ROOT>/lib64/cmake/amd_comgr

# 3. HIP clang wrapper（补 AMD GPU 优化标志）
cat > $BUILD/hip_wrapper.sh << 'EOF'
#!/bin/bash
exec <DTK_ROOT>/llvm/bin/clang++ \
  --gcc-toolchain=<GCC_ROOT> \
  -mllvm -amdgpu-early-inline-all=true \
  -mllvm -amdgpu-function-calls=false \
  "$@"
EOF
chmod +x $BUILD/hip_wrapper.sh

# 4. CMake 配置 + 编译
$CMAKE $SRC \
  -DGMX_BUILD_OWN_FFTW=ON -DGMX_GPU=HIP -DGMX_MPI=ON \
  -DCMAKE_C_COMPILER=$GCC_HOME/bin/gcc -DCMAKE_CXX_COMPILER=$GCC_HOME/bin/g++ \
  -DCMAKE_HIP_COMPILER=$BUILD/hip_wrapper.sh \
  -DCMAKE_PREFIX_PATH=<DTK_ROOT> \
  -Damd_comgr_DIR=<DTK_ROOT>/lib64/cmake/amd_comgr \
  -DGMX_SIMD=AVX2_256 -DGMX_GPU_FFT_LIBRARY=rocFFT \
  -DGMX_GPU_NB_DISABLE_CLUSTER_PAIR_SPLIT=ON \
  -DGMX_GPU_NB_NUM_CLUSTER_PER_CELL_X=1 -DGMX_GPU_NB_NUM_CLUSTER_PER_CELL_Y=1 -DGMX_GPU_NB_NUM_CLUSTER_PER_CELL_Z=1 \
  -DGMX_HIP_TARGET_ARCH=gfx906 -DAMDGPU_TARGETS=gfx906 -DGPU_TARGETS=gfx906 \
  -DCMAKE_BUILD_TYPE=Release
make -j8

Full script:<USER_HOME>/scripts/gromacs_cmake28_build.slurm(can directly sbatch recurrence).

Feature changes (GROMACS 2023.2—2026.3)

  • Native HIP backend: 2026.3 turns AMD/HIP into a first-class citizen backend for the first time, and all GPU kernels can follow the official native HIP code path (no longer relying on the translation layer or SYCL).
  • AMBER force field + OPC/OPC3 water model(2026); per-amino acid CMAP type (2025).
  • Neural network potential energy (NNP/ML): PyTorch interface, link atom, pairlist input, EMLE electrostatic embedding.
  • enhanced sampling: Native Colvars (2024), PLUMED interface (MDModules).
  • Performance Algorithm: HMR (hydrogen mass redistribution), AWH improvements, H5MD trajectory output, NVSHMEM halo exchange, etc.
