⚙️ 2. 构建过程与兼容性分析

2.1 路径一：GPU 包 + HIP 后端

构建配置：-D PKG_GPU=ON -D GPU_API=HIP -D HIP_ARCH=gfx936

初始现象：编译可完成，但运行阶段停留在 HIP 初始化过程。

原因分析：DTK 的 CMake 配置为 GPU 库加入 -xhip 编译标志，使 hipcc 为相关 C++ 文件生成 HIP 设备代码，进而影响初始化流程。

适配结果：设置 AMDGPU_TARGETS="gfx936" 并禁用 HIP_USE_DEVICE_SORT 后，可完成编译与运行。在本报告的测试规模与参数下，GPU 包用时为 Kokkos 路径的 4.6–6.3 倍（详见第 6 节）。

2.2 路径二：KOKKOS 包 + HIP 后端

构建配置：-D PKG_KOKKOS=ON -D Kokkos_ENABLE_HIP=ON

初始现象：编译可完成，运行阶段报告 running kernels compiled for gfx906 on gfx936。

原因分析：Kokkos 4.6.2 未内置 gfx936 架构配置，自动检测回退至 gfx906。由于目标指令集不一致，生成的设备代码无法在 gfx936 上加载，并返回 hipErrorInvalidKernelFile。

2.3 Kokkos gfx936 适配方案

实现思路：在 Kokkos 的 CMake 配置与 HIP 后端代码中补充 gfx936 架构定义。

📄 修改 1：lib/kokkos/cmake/kokkos_arch.cmake
在 SUPPORTED_AMD_ARCHS 列表中添加 AMD_GFX936，对应标志 gfx936；将 gfx936 放在 gfx906 之前，确保自动检测优先匹配 gfx936；在架构检测循环中添加 936 的正则匹配分支。
📄 修改 2：lib/kokkos/cmake/KokkosCore_config.h.in
添加 #cmakedefine KOKKOS_ARCH_AMD_GFX936。
📄 修改 3：lib/kokkos/core/src/HIP/Kokkos_HIP_Instance.hpp
在 HIPTraits 的 WarpSize 条件编译中添加 defined(KOKKOS_ARCH_AMD_GFX936)。海光 BW 系列 wavefront 大小为 64，与 gfx906/gfx908 相同。
📄 修改 4：lib/kokkos/core/src/HIP/Kokkos_HIP_IsXnack.hpp
在 gpu_arch_can_access_system_allocations 函数中添加 defined(KOKKOS_ARCH_AMD_GFX936) 到 return false 分支。海光 DCU 不支持系统内存访问。

  -D CMAKE_C_COMPILER=gcc \

⚖️ 6. GPU 包 vs Kokkos 性能对比

6.1 测试目的

验证是否存在比 Kokkos 更高效的 GPU 加速方案。GPU 包使用手写优化的 HIP 内核，理论上可能比 Kokkos 的通用抽象更高效。

6.2 GPU 包构建适配

关键适配点
  • AMDGPU_TARGETS="gfx936" 和 GPU_TARGETS="gfx936"：防止 DTK 自动添加多个架构导致 --offload-arch 泄漏到 g++
  • HIP_USE_DEVICE_SORT=OFF：避免链接 hip::device，防止 -xhip 标志被传递给 g++

6.5 GPU 包较慢的原因分析

📌 邻居列表在 CPU 构建：GPU 包输出显示 "Neigh mode: Hybrid (binning on host)"，每次重建都需要 CPU→GPU 数据传输，而 Kokkos 完全在 GPU 上构建邻居列表
📌 GPU 包设计偏向多 GPU：单 GPU 场景下开销较大，需要额外的 fix gpu 命令管理资源
📌 Kokkos 更深度集成：所有计算（pair, neighbor, comm）都在 GPU 上，数据传输最少化

6.6 海光原生编译器确认

通过分析 DTK 工具链，确认当前方案已经使用海光原生编译器：

# hipcc 最终调用海光原生 dcc 编译器
hipcc → <DTK_ROOT>/dcc/bin/dcc
           ↓
  海光 ISA bitcode: oclc_isa_version_936.bc

Kokkos 的 AMD_GFX936 只是命名约定，底层编译使用海光自己的 dcc 编译器 + 海光 ISA bitcode，已经是原生编译。

🎯 8. 最终结论

测试结论

在本报告列明的软件版本、模型规模与运行参数下，Kokkos + HIP 后端 的运行时间约为 GPU/HIP 路径的 1/4.6–1/6.3，因此可作为该测试场景的优先方案。该结论不直接外推至其他模型、规模或软件版本。

关键结论

✅ Kokkos 方案已使用海光原生编译器：hipcc 最终调用 dcc（海光 DCU C 编译器），生成海光 ISA 代码，已是原生编译
✅ 本次测试中 Kokkos 用时更短：32K 原子场景约为 GPU 包的 1/6.3，256K 原子场景约为 1/4.6
✅ GPU 包较慢的根本原因：邻居列表在 CPU 构建（"binning on host"），而 Kokkos 完全在 GPU 构建
✅ gfx936 是海光原生架构：不是"假装 AMD"，DTK 包含海光专有的 ISA bitcode（oclc_isa_version_936.bc）
✅ DCU 能效比极高：满负荷运行温度仅 55°C，功耗 86-122W

后续优化方向

方向 说明 预期收益
Kokkos 参数调优 针对 gfx936 的 80 CU 架构调整 tile size、chunk size 可能 5-15%
多 GPU 并行 使用 MPI + 多 DCU 卡 线性扩展
混合精度 使用 single precision 进一步提升 可能 1.5-2×
